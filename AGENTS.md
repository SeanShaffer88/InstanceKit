# InstanceKit — agent notes

- The ack is the contract: `forwarded` is true only when the primary's `{"ack":true}` frame arrived within `forward_timeout_ms`. A write that "succeeded" is not delivery — the primary may have died before queueing. Do not add a path that reports forwarded without the ack round-trip.
- A secondary must close its handle to the existing mutex immediately (in `create_mutex`, on the `ERROR_ALREADY_EXISTS` path). A secondary that keeps the handle open keeps the mutex name alive after the primary exits, and the next starter would forward into a pipe nobody serves. This is the kit's easiest bug to reintroduce and the hardest to notice.
- Every wait in the listener thread includes the stop event (connect, read, write), and `PrimaryHandle::release` sets it and JOINS. A release that detaches "for responsiveness" silently breaks the no-leaked-thread guarantee; a wait without the stop event makes join hang forever.
- The listener serves exactly one frame per connection, then disconnects: queue it, ack it, drop the instance. Malformed or oversized frames get NO ack (disconnect silently) — acking garbage would teach secondaries that undelivered args were delivered.
- The frame cap is enforced twice on purpose: encode rejects > 1 MiB payloads, and the decoder rejects an oversized DECLARED length the moment the 4-byte header completes, before buffering any payload. Removing the header check turns a 4-byte lie into a 4 GiB allocation wait.
- The state machine (`acquire_with`) and everything it touches — name validation, framing, envelope, spec parsing, mailbox, registry — are pure and host-tested. `platform.rs` is the only file allowed to touch Win32, and it exposes exactly the `InstanceBackend` trait. Do not grow a second, divergent path around the trait.
- Poll semantics: `timeout_ms` above 60 000 is CLAMPED (documented), not an error; the mailbox drains queued messages even after close, then returns null promptly. Each message goes to exactly one poll — do not "broadcast" to concurrent pollers.
- Error discipline is family-standard: malformed JSON / unknown keys / duplicate keys = `ERR_PARSE`; missing / wrong-typed / out-of-alphabet values = `ERR_INVALID_ARG`. The JSON engine (src/json.rs) is the family design — duplicate keys are a PARSE ERROR by design.
- Zero dependencies; Win32 bindings are hand-declared in `src/platform.rs` and every extern block carries `#[link(name = "kernel32")]` — check/clippy cannot catch a missing one (LNK2019); CI's real build is the link gate.
- Windows runtime is Unverified until a field pass on a real Windows machine runs the integration scenario (see docs/PARITY.md). Local gate green is Linux evidence — say so.
- Gate: WinDevKit tools/gate.sh (fmt + clippy both targets + full tests + windows all-targets check).
